# 核心失守與裂隙反攻
2026-09-13。完整 Demo 的一個交付單元；未完成整局平衡、手機安裝或商店發行。

## 玩家流程
營火就是要保護的核心，預設 180 生命。敵人會攻擊附近的騎士、居民或核心，途中完好的城牆會攔住進攻。核心歸零或騎士倒下皆結束本局；停止生產、時間、敵人、移動與投入，提供重開與新地圖。失敗圖示以營火／愛心區分原因。

建立營地後，受損核心的現場互動優先改為充能：填兩格龍晶回復 60，上限為最大生命。部分投入不補血，補滿後恢復普通聚落升級。這是即時充能，不需工匠施工；同一批龍晶要在自己、居民、修牆與核心之間分配。

探索兩端可發現龍裂隙，未探索時不顯示其場景物件。升到二級聚落、熬過一晚、已有工匠後，可在裂隙投入四格龍晶。缺少的條件直接以營火等級、熬夜數、工匠圖示顯示，不當作消耗材料。

付款後，最近的空手工匠前往裂隙；已搬起的貨物先入庫，未搬起的採集工作釋出但保留進度。出征優先於普通工作及傍晚回防，因此玩家必須考慮出發時機。工匠失去職業會釋出名額，由另一位工程居民接手，無須重付。

工匠抵達且騎士在 160 單位內、接近地面時，裂隙生成兩名守門者。最低 90 生命、18 傷害，若當天夜襲數值更高則採較高值。守門者使用現有敵人戰鬥與美術，不是已完成的專屬龍王 Boss。裂隙 180 單位內有活敵人時，封印暫停；清出安全區、騎士陪同、工匠就位才累積預設 8 秒工作。騎士暫離會保留進度，守門者只生成一次。

封住一側後，那側待出生及未來夜襲取消，已出現的敵人仍要處理。兩側封印且場上殘敵清空才顯示皇冠、2/2 並結束本局；舊「王國建立」只是建設里程碑，不能觸發勝利。敵人可被引離封印區，但未消滅的殘敵仍會阻止最終勝利。

## 維護入口
campaign.tres 的 Core and Expedition：核心生命、充能量、封印秒數、守門者生命與傷害。Crystal Prices 的 core_charge／rift 鍵控制龍晶格數，舊資源缺少這兩個鍵時沿用 2／4 的預設，可新增 Dictionary 鍵覆寫。

CampaignMission 只保存核心、裂隙與勝敗規則；RiftWorkforce 負責工匠工作優先順序。CampaignSession 整合出征、實際敵人及夜襲來源。呈現層讀狀態畫圖示與能量動畫，不發資源或決定勝敗。原有石材搭配程序像素裂隙，沿用現有原創素材，沒有新增 AI 圖片。

## 驗證與限制
TDD 分段先得到核心／裂隙缺少的預期失敗，再補實作；場景測試先重現 5 個勝敗 UI 錯誤。行為測試覆蓋實際攻城、雙側牆保護、充能格、探索與門檻、護送、一次性守門者、工匠替補、搬運保留、封印停敵、殘敵與敗北優先。真實場景驗證觸控投入、暫停、結局輸入凍結、R 重開與新地圖。

乾淨標準設定完整 tools/check.sh：834 項 Godot 斷言（648 行為、186 場景），2 個 Python 建置測試，零失敗；分層、匯入、錯誤掃描與入口啟動通過。原生畫面以 tools/preview_mission.gd 重現，檢查核心充能／失守、解鎖條件、守門者、完整 8 秒封印及勝利。

[封印動畫](../previews/rift-seal-v001.gif)、[失守](../previews/core-loss-v001.png)、[勝利](../previews/rift-victory-v001.png)。這些是可控制的場景 fixture；測試跳過經濟建設並使用高傷害測試劍縮短戰鬥，不是預設預算或真人通關證據。

[新規則 18 組固定守軍測量](balance-core-rifts.json) 只預建雙側牆、配置固定守軍，騎士不參戰、不維修。首夜只有一守備兵時左側被突破，約 40 秒核心失守；一守備兵加一獵人雖左牆破，仍清掉敵人保住核心。兩守備兵及雙側石牆可過第三夜，牆剩左 28／右 2；第五夜核心失守，兩守備兵約 33.2 秒，加兩獵人約 47.8 秒。這說明混編有延後崩潰效果，不代表已達到難度適中。
