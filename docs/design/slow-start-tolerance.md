# 開局慢一分鐘的恢復性測量
2026-09-13。遊戲基底 236b205；本轮只改測量工具，不改遊戲數值。

## 要回答的問題

在未建營火、標準 12 顆龍晶的開局，前一分鐘完全不輸入、世界仍正常推進，之後採既有騎士／居民投資路線，是否已不可恢復？這是明確的單一錯失情境，不是完整新手行為模型。

沿用原生 Node 物理與投入按鈕，三種子 × 兩路線 × 立即／延後，共十二局，同版本對照。每局上限 1800 秒遊戲時間；沒有跳日、暫停、傳送、贈晶或預建。延後組首次行動均在第 60 秒，當時仍在 x=30、營火未建、背包 12、地上晶體 0，八人仍是流浪者。只有操作器停止输入，遊戲時間不停止。

十二局皆雙裂隙封印勝利。延後組約 12.6–25.8 分鐘；四組變慢、兩組變快，因此不能只把延遲看成最後加 60 秒。操作器依日夜、工作與庫存選擇下一項行動；結果與這些條件改變後的策略路徑有關，未單獨分解每項原因。

延後組居民失職合計 8 次，立即組 3 次；不是永久死亡或不同人物數。種子 1 騎士路線在 480／720／960／1200 秒樣本見左牆生命為零，最後仍通關，並非全程完整防線。種子 1 延後居民路線最後左牆仍為零，不能把勝利當成每一面牆都修好了。

新指標逐物理幀觀察核心最低生命，十二局皆 180；騎士生命累計損失皆 0。操作器能讀精確敵人預警並自動閃避，也熟悉建設條件，這解釋了證據的限制，不能據此宣稱真人會毫髮無傷或難度已適中。

所有紀錄通過龍晶淨變化守恆：12＋觀察到的增加－觀察到的減少＝終局背包＋地上。這不是逐筆毛收入／付款帳本，同幀收支可互相抵銷。

## 設計判斷

目前不因這個情境增加首日時間或減弱怪物。已有「慢一分鐘仍可恢復、但常有時間與居民代價」的具體證據；真實新手可能迷路、買錯器具或未理解封印，仍需真人回饋。已提出一次首晚試玩回饋問題，尚未收到回答，不用更多自動綠燈代替玩家。

## 重現與限制

先用來源 tree 的乾淨副本匯入素材，再執行：

```sh
Godot --headless --fixed-fps 60 --path /path/to/clean-project --script res://tools/play_slow_start.gd -- 1 knight /tmp/slow.json 1800 reactive
Godot --headless --fixed-fps 60 --path /path/to/clean-project --script res://tools/play_campaign.gd -- 1 knight /tmp/immediate.json 1800 reactive
```

切換 seed 為 7／42、route 為 residents。實際 Godot 路徑依本機安裝；--fixed-fps 60 只取消即時等待，物理每步仍是 1/60 秒。source tree、工具雜湊、原始十二局與檢查見 [驗證報告](../reports/slow-start-v001/manifest.json)。完整 checks 為 1187 個 Godot 斷言與 10 個 Python 測試。
