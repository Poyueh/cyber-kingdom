# Kingdom 參考與可玩 Demo 驗收
更新：2026-09-13。此文件追蹤本次完整目標；居民回防只是第一個交付單元，不能代替完整 Demo 或四平台驗收。

## 研究結論與版本界線
參考使用者指定的 [Kingdom 系列](https://store.steampowered.com/franchise/kingdom?l=tchinese)。實作以 Two Crowns 的「探索、投入、居民自治、日夜防守、向外進攻」為主要參考，不把各作與 DLC 的價格／兵種混為同一規則，也不複製角色、世界、美術或音樂。

[官方 Two Crowns 開發者新手指南](https://steamcommunity.com/app/701160/discussions/0/4849904828217616805) 明確建議先立營地、兩側城牆與弓手；用狩獵、寶箱與商人取得早期收入，派工匠清樹拓展空間，探索時在日落前返回。清樹會影響野生動物與招募地，收入、防線與擴張互相牽動。晚間防禦再逐步銜接船隻、其他島嶼與消滅敵源。這說明樂趣不只是自動戰鬥，而是玩家在有限時間與收入下決定先投資什麼。

[官方遊戲頁](https://kingdomthegame.com/kingdom-two-crowns/) 與 [官方上市介紹](https://www.kingdomthegame.com/news/2018/12/11/welcome-to-kingdom-two-crowns) 將持續戰役與合作列為 Two Crowns 的特色；本 Demo 先做單人一座島，不承諾同步製作雙人或全系列多島內容。[Nintendo 商品介紹](https://www.nintendo.com/en-ca/store/products/kingdom-two-crowns-switch/) 也將建設、探索、防守與征服串成目標，支持 Demo 必須有可主動完成的終局。

居民受擊退回流浪者、按器具就職、丟晶招攬等，已由使用者明確指定，作為本專案驗收需求。社群 Wiki 可輔助查找術語，但本輪未可靠驗證各版本精確價格、日程與職業上限，不能把它們當成已研究確定的數值。

## 自己的遊戲承諾
人類靠龍晶驅動機械義肢，在魔法與巨龍的世界建立最後避難所。騎士能打怪與改裝，但同一批龍晶也要招募居民、供應器具與修城。玩家必須能看懂「花在自己」與「花在聚落」各解決什麼問題。

首個 Demo 目標是一座種子生成、可重玩的島，一輪約 20–30 分鐘是待測試的設計目標。首輪有圖示引導與可恢復的小失誤；熟悉後仍有拓展順序、資源位置和敵人組合的取捨。它必須有明確勝敗與重試，不能把存活三晚的條件旗標當作完整終局。

## 開發次序與目前缺口
1. 已完成首個單元：依回程距離提早收工，保留職業／工作／貨物；獵人夜間對敵射擊。測試與測量見 resident-night-cycle.md。
2. 已接上初始雙側防線／敵襲、居民分防與方向預警；已加入核心失守與裂隙反攻終局，見 core-and-rifts.md；接著向外拓展防線。
3. 可恢復招募、獵物與草本再生已接通（frontier-renewal.md），有限騎士成長已接通（knight-growth.md）；接著完成外擴防線、至少三個種子的完整遊玩與不同投資路線測試。
4. 平行準備匯出環境；完成觸控、存續檔與安全區驗收，再簽署測試包。

現有不足：兩個初始固定防線，尚無向外拓展防線；招募／獵物／草本已有再生、礦藏與木材仍有限；已加入三階劍術／電容、聚落門檻與封頂充能，但尚缺兩條路線的整局驗證；核心失守與雙裂隙終局已接通，但尚無完整戰役存檔與預設預算通關證據。固定守軍測試中的「天亮」不等於勝利；新戰役敵人會朝核心進攻，不再因居民全失就自行離場。

## 平衡驗證方法
先以固定步長、無騎士介入的守軍測量建立基線，再用完整開局流程測收入和建設時機。分別記錄首晚建設是否趕得上、晶體取得／消耗、居民損失、騎士承傷、各夜防線存量與通關時間。每個種子跑「優先騎士」與「優先居民」；只有自動測試與真人試玩均有證據後才能稱為難度適中。

核心規則已再執行 18 組基線，見 core-and-rifts.md 與 balance-core-rifts.json；兩守備兵與雙側石牆可守第三晚，第五晚失守。這仍只是預建防線測量，需要在完整經濟與騎士成長接好後再定難度。

## 裝置與匯出狀態
使用者已確認：iPhone 17e、iPhone 16 Pro Max。這是可用測試裝置清單，不代表已完成安裝或測試；Android／Windows 實機與 Apple 開發者帳號待確認。

本機 Godot 4.7.2 已核對。尚缺完整 Xcode（目前僅 Command Line Tools）；預設 Android SDK 位置沒有 SDK。Godot 官方相同版本匯出模板已安裝；Mac／Windows 開發測試包已匯出，驗證與限制見 ../BUILDING.md。iOS／Android 尚未交付安裝包，四平台目標未完成。
- [Godot iOS 匯出](https://docs.godotengine.org/en/stable/tutorials/export/exporting_for_ios.html)：需要 macOS、完整 Xcode、模板與真實團隊／Bundle 設定；後續在 Xcode 建置與裝置部署。
- [Godot Android 匯出](https://docs.godotengine.org/en/stable/tutorials/export/exporting_for_android.html)：依文件配置 JDK／Android SDK／簽署，再驗證 APK。商店交付另準備正式金鑰與 AAB。
- 簽署帳號、私鑰不放 Git。未驗證的手機、作業系統或證書不填成完成。
